# 便宜机票 CheapTrip

目标：用户输入出发地和预算，系统自动发现“没钱也想出去玩”的低价往返旅行机会。

## 核心规则

- 每个候选旅行必须同时有去程和返程
- 往返总价 = 去程价格 + 返程价格
- 预算指整个往返行程的总预算
- 每个目的地只保留最低往返组合
- 最终按往返总价从低到高排序
- 没有明确票价时不猜价格
- 同一航段、同一天的价格只查询一次
- 航班数据查询失败会有限次数重试

当前使用两个单程报价计算往返总价，因此 price_source=outbound + inbound。
这个值代表两个单程报价之和，不应伪装成航空公司或 OTA 的单一往返订单总价。

## 当前版本

### 搜索引擎

1. 解析出发城市或 IATA 机场代码
2. 获取候选目的地
3. 根据旅行天数生成所有合法出发/返程日期组合
4. 计算所有需要的唯一航段
5. 使用有界线程池并发获取航段价格
6. 对失败请求自动重试
7. 将成功的去程、返程价格放入内存缓存
8. 本地组合所有日期
9. 按往返预算过滤
10. 每个目的地保留最便宜的完整往返组合
11. 最终按价格、旅行天数、日期排序

### API

GET /api/health

POST /api/search

请求示例：

{
  "origin": "沈阳",
  "budget": 500,
  "days_ahead": 30,
  "min_trip_days": 2,
  "max_trip_days": 5,
  "max_destinations": 10,
  "currency": "CNY"
}

返回结果包含：

- 去程价格
- 返程价格
- 往返总价
- 出发日期
- 返程日期
- 旅行天数
- 价格来源
- 搜索统计信息

## 数据源说明

项目当前使用 fast-flights >= 3.0.2。它是第三方 Google Flights scraper，而不是 Google 官方航班 API。

因此应用层已经做到：

- 不猜价格
- 不把航班时长、时间戳等数字误认为票价
- 价格解析失败时跳过该航段
- 单个请求失败不会让整个搜索立即崩溃
- 有限重试
- 最终全部航段失败时返回明确的数据源错误

但外部抓取数据源本身无法由本项目保证永久可用。上游项目公开记录中也存在解析、Cookie/请求以及返回数据结构变化相关的问题，因此生产环境最终应该接入稳定、获得授权的商业航班数据源。

## 后续生产化方向

核心搜索算法已经完成 V2 的“缓存 + 并发 + 重试”基础能力。后续生产化可以在不改变核心业务规则的情况下增加：

1. 更完整的国内/国际机场数据库
2. 真正的 round-trip provider 报价
3. Redis/SQLite/PostgreSQL 价格缓存
4. 后台任务与搜索进度
5. 多数据源聚合与故障切换
6. 价格历史和低价趋势
7. 用户订阅与降价提醒
8. 微信/邮件通知
9. 价格过期时间与重新验证
10. 航班详情、航班号、经停、行李等信息

这些功能都应继续遵守最重要的一条：用户看到的“便宜”必须来自真实可验证的航班价格，而不是模型猜出来的价格。
